# FinConverter — контекст для продолжения работы

Telegram-бот с мини-аппом для студентов Финансового университета («финашка»):
человек присылает фото конспектов, сканы или PDF, бот собирает из них один PDF.
Пользователь общается по-русски, отвечать тоже по-русски.

## Что уже сделано (на 30.10.2026)

- **Бот** (`app/bot.py`, aiogram 3, long polling): фото по одному, альбомом или файлом
  (JPG/PNG/HEIC), склейка PDF. На альбом бот отвечает одним обновляемым
  сообщением «В PDF N стр.», а не на каждое фото. Текстовое сообщение становится
  именем файла. Команды: `/pdf`, `/title`, `/ocr`, `/clear`, `/help`.
- **Сборка PDF** (`app/pdf.py`): режимы «Цвет / Ч/Б / Скан» (скан убирает тени,
  фон становится белым), формат «как фото / A4 с полями», три уровня качества.
  Учитывается лимит Telegram: бот отправляет до 50 МБ, скачивает до 20 МБ.
- **Титульный лист** (`app/title.py`, reportlab): шаблон Финансового университета,
  A4, Times New Roman 14, поля по ГОСТ 7.32. ФИО, группа и дисциплина
  запоминаются (`data/_titles/<uid>.json`), тема и переключатель сбрасываются
  после каждого PDF. Нужен шрифт Times New Roman или Liberation Serif.
- **Мини-апп** (`webapp/`, vanilla JS + SortableJS, всё своё: шрифт Golos Text и Sortable лежат в
  `webapp/fonts/` и `webapp/vendor/`, внешних CDN нет, кроме `telegram-web-app.js`). Интерфейс **«Объектив»**
  (вариант A, выбран по макету): экран «старт» с тремя действиями (Снять, Из галереи, PDF-файл) и
  стопкой листов, которая при выборе файлов вырастает в страницу редактора (`flyToEditor` в `app.js`), редактор
  со страницей крупно (карусель со свайпом, режим Цвет / Ч/Б / Скан сегментом под ней, плёнка миниатюр
  внизу: долгое нажатие — перестановка), поворот и удаление поверх страницы (удаление можно вернуть
  5 секунд), шторки «Настройки» и «Титульный лист» (с живым HTML-превью), шторка распознавания, экран
  проверки текста (фото сверху, текст ниже, правки подсвечены, по нажатию фото приближается к слову и
  выезжает карточка «было, стало, почему» с кнопкой «Вернуть»; переключатель «Исправлено / Оригинал»),
  экраны «готово» и «закрыто». Затвор «PDF» при сборке крутит кольцо. Скрытая диагностика:
  7 нажатий по логотипу или счётчику страниц показывают размеры окна и поля безопасной области.
  Код: `app.js` (ключевая сверка слотов и миниатюр без перерисовки всего, слои со стеком для кнопки
  «Назад», демо-сервер `demoApi` для `?demo`), `style.css`, `index.html`.
- **API мини-аппа** (`app/web.py`, aiohttp в том же процессе, что и бот):
  авторизация по подписи `Telegram.WebApp.initData` (HMAC от токена), превью
  страниц по подписанным ссылкам.
- **Деплой и `/update`**: бот на VDS (Ubuntu 24, Амстердам, Docker + Caddy) по адресу
  `finconverter.194-41-113-226.sslip.io` (контейнер на `127.0.0.1:8082`; на сервере ещё два
  чужих бота и `starosta` на порту 8000, их адрес `194-41-113-226.sslip.io` не трогать).
  `/update` (`app/updater.py`, только `ADMIN_IDS`) делает `git pull --ff-only` в смонтированном
  клоне `/opt/finconverter` и перезапускает процесс, Docker поднимает его снова.
  `PROXY_URL` нужен, если Telegram недоступен напрямую (локально из РФ).
  **Закрытый режим**: пока ботом и мини-аппом могут пользоваться только `ADMIN_IDS`
  (`admin_only` в `app/bot.py`, `auth_middleware` в `app/web.py`, экран «пока закрыт» в
  мини-аппе). При пустом `ADMIN_IDS` закрыто для всех.
- **Распознавание текста** (только печатный, rus+eng, Tesseract), два способа:
  1. **В мини-аппе** (основной, по одобренному макету): кнопка «Aa» в редакторе, шторка с прогрессом и
     очередью (две стадии: «Распознаю» и «Проверяю текст»), экран проверки (фото сверху, текст ниже, его
     можно править), экран результата (документ Word, PDF из текста, копирование). Бэкенд:
     `app/recognize.py` (фоновая задача на человека, мини-апп опрашивает `GET /api/ocr`), текст страницы
     лежит в `Item.text` (абзацы, помеченные слова между `MARK_OPEN`/`MARK_CLOSE` из `app/ocr.py`),
     пометки с метаданными в `Item.marks` (по порядку в тексте: kind, old, new, why, on, box), признак
     проверки в `Item.checked`, правка `PUT /api/items/{id}/text` (text и marks), экспорт
     `POST /api/export` (`app/document.py`: docx и PDF по ГОСТ 7.32, уходят в чат, `text` для копирования).
     **Проверка текста моделью** входит в распознавание (`app/proofread.py`): если на сервере задан
     `ANTHROPIC_API_KEY`, текст каждой страницы (без фото) уходит модели Claude (`PROOFREAD_MODEL`, по
     умолчанию `claude-haiku-5-5`, структурированный ответ). Она возвращает правки, сервер применяет их
     сам, только если фрагмент встречается в абзаце один раз и не пересекается с другой правкой. Само
     исправляется то, что очевидно: ошибки распознавания (`ocr`), правописание (`spell`), пунктуация
     (`punct`). Смысл (`ask`) только предлагается: слово подчёркнуто, текст не меняется, пока человек не
     нажмёт «Заменить». Любую правку можно вернуть. Проверка идёт параллельно с чтением следующей страницы.
     Без ключа, при сбое API или отказе модели остаётся обычный распознанный текст: сомнительные слова
     Tesseract помечены (kind `un`), на экране «Проверка недоступна». В шторке распознавания мелкая строка
     о том, что текст уходит во внешний сервис. Принятые по умолчанию решения (пользователь не отвечал):
     смысл только предлагается, лёгкая модель, строка про сервис показывается каждый раз, кнопка «Справка»
     со старта убрана (она ничего не делала).
  2. **Команда `/ocr`**: невидимый текстовый слой поверх фото в обычном PDF (поиск и копирование).
  Очередь `OCR_WORKERS` (по умолчанию 2) и лимит `OCR_DAILY_PAGES` (100/сутки на человека, админам
  нет) общие для обоих способов. Рукопись нужна позже отдельным облачным режимом.
  Проверено: Tesseract 5.3, API целиком (загрузка, распознавание, правка, экспорт), сценарий мини-аппа
  в браузере на демо и на настоящем API в обеих темах, проверка текста с подставной моделью. Не
  проверено: реальный вызов Claude (ключа в среде не было, форма запроса сверена с SDK), внутри
  настоящего Telegram, фото с телефона.
- **Логотип**: лист с загнутым уголком цвета лайм, строки на нём образуют F
  (`assets/logo.svg`, аватарка для BotFather — `assets/bot-avatar.png`).
- **Макет** на канвасе Claude: https://claude.ai/artifact/QWpPxUsmYCgKVYid3dpAuS
  (светлая и тёмная тема всех экранов, лист с логотипом). Ссылка приватная.

## Решения по дизайну (пользователь их уже выбрал, не откатывать)

1. Первый вариант (шрифт Unbounded, лаймовые бейджи, карточки) отклонён:
   «не должен быть похож на ИИ».
2. Нативный стиль настроек Telegram отклонён: «нужен современный, модерн».
3. **Текущий стиль («Объектив»)**: шрифт Golos Text, тёмная тема родная, светлая рядом; чёрный/белый
   монохром и один жёлтый акцент `#ffd60a` (светлая тема `#ffc800`). Страница крупно, плёнка, затвор.
   Лайм — только в логотипе. Без градиентов-подложек, свечения, эмодзи и мультяшности («не надо
   придумывать мультяшное»). Прежний стиль (Onest, синий акцент, сетка в две колонки) заменён.
4. Тёмная тема обязательна. Тема берётся из `Telegram.WebApp.colorScheme` и
   меняется по событию `themeChanged`.
5. Плавные анимации везде: страницы и миниатюры переезжают на новые места, появление каскадом,
   шторки въезжают и уезжают. `prefers-reduced-motion` отключает анимации.
6. **Сначала макет, потом согласование, и только потом код.** Это касается любых
   визуальных изменений (анимации, экраны, заставки) и любой новой функции с экраном
   или сценарием в мини-аппе, в том числе бэкенда под неё: пока пользователь не одобрил
   макет, код не писать. Макет делать обычной HTML-страницей (артефакт),
   **не доской/холстом Design**, и в конце задавать вопросы, которые надо решить.
   Если непонятно, чего хочет пользователь, сначала уточнить, а не писать код.
7. **Заставка при входе — «Тихий вход»** (выбрана по макету из трёх): логотип проявляется
   за 0,24 с, держится минимум 0,45 с (`SPLASH_MIN` в `app.js`), затем гаснет за 0,27 с, а
   интерфейс выезжает. Показывается при каждом открытии, без перелёта логотипа.
   Открыто: тонкая обводка плитки логотипа в тёмной теме; показывать только раз в день?

## Как запускать

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env              # вписать BOT_TOKEN
./scripts/dev.sh                  # туннель cloudflared + бот; без cloudflared — бот без мини-аппа
.venv/bin/python -m app.demo      # только интерфейс, без токена: http://127.0.0.1:8080/?demo
```

- `scripts/dev.sh` ищет `cloudflared` в PATH или в `bin/` (папка `bin/` в
  `.gitignore`, бинарник скачивается отдельно). Адрес quick-tunnel меняется при
  каждом запуске, бот сам обновляет кнопку меню «Редактор».
- Демо на широком экране показывается в рамке телефона 390×844 с кнопкой смены
  темы. `?demo&inner` — без рамки.
- В Chrome у пользователя `localhost` принудительно уходит на HTTPS (запомненный
  HSTS), поэтому демо открывать по `http://127.0.0.1:8080/?demo`.
- Продакшен: `Dockerfile` (ставит `fonts-liberation` для титульника). Нужны
  переменные `BOT_TOKEN` и `WEBAPP_URL` (публичный HTTPS-адрес, который ведёт
  на порт 8080 контейнера), а `DATA_DIR` стоит вынести в том (volume).

## Проверено и не проверено

- Проверено: сборка PDF во всех 18 сочетаниях настроек, API (подпись, превью,
  порядок, поворот, сборка, титульник) — тестовым скриптом. Мини-апп — в
  браузере в демо-режиме, светлая и тёмная тема.
- Бот запущен у пользователя (@finconverter_bot), polling работает.
- **Тесты**: `tests/` (pytest, `pip install -r requirements-dev.txt`, затем `pytest`): хранилище и
  параллельная загрузка, 18 сочетаний настроек PDF, распознавание и очередь, авторизация и закрытый
  режим, API распознавания и экспорта. Тесты с Tesseract пропускаются, если его нет.
- Новый интерфейс проверен в Chromium (Playwright): демо и настоящий API (загрузка JPG и PDF, поворот,
  удаление с возвратом и фиксацией, перестановка, режимы и настройки, распознавание с Tesseract, правка
  текста, экспорт в Word, сборка, закрытый режим, офлайн, малый экран 360×640, `prefers-reduced-motion`,
  обе темы). Ошибок JS нет.
- **Не проверено**: мини-апп внутри настоящего Telegram на телефоне, WebKit/iPhone, фото с реального
  телефона, долгое нажатие для перестановки на тач-экране. Открытый баг: «сдвиг влево» на главном экране
  после заставки у пользователя на телефоне и в десктопном Telegram. В новой вёрстке `body` закреплён
  (`position: fixed`), документ не прокручивается и полосы нет; причина на телефоне не найдена, в Chromium
  не воспроизводится. Если повторится: открыть диагностику (7 нажатий по логотипу) и прислать текст.
